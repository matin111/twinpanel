# TwinPanel — پنل جامع فروش، مدیریت و زیرساخت VPN

**TwinPanel یک پلتفرم Self-Hosted برای فروش و عملیات VPN است؛ با ۱۶ خانواده پروتکل VPN/Proxy، مدیریت اشتراک و تمدید رزروی، ربات تلگرام، پرداخت و کیف پول، نمایندگی، اپ هوشمند چندبرندی، مدیریت نود و تانل، مسیر اضطراری DNS، مانیتورینگ و آپدیت امن.**

هدف TwinPanel این است که اپراتور مجبور نباشد برای فروش، مدیریت کاربران، ربات تلگرام، پروتکل‌ها، سرورها و تانل‌ها چند سیستم جداگانه داشته باشد.

```text
کاربر / نماینده / ربات تلگرام / فروشگاه وب
                    ↓
                پلن و خرید
                    ↓
              ساخت اشتراک
                    ↓
           تحویل Credential
                    ↓
          ۱۶ پروتکل VPN/Proxy
                    ↓
          نود ایران / Relay / Exit
                    ↓
             Tunnel / Outbound
                    ↓
                 اینترنت
```

## امکانات تازه و مهم

- **تمدید رزروی:** تمدید خریداری‌شده در صف می‌ماند و پس از پایان دوره یا حجم قبلی، در شرایط معتبر خودکار فعال می‌شود؛ نام کاربری و کانفیگ‌های قبلی حفظ می‌شوند. وضعیت صف و تاریخچه فعال‌سازی در مدیریت اشتراک قابل مشاهده است.
- **کیف پول و تأیید پرداخت:** شارژ، خرید، تمدید، بررسی رسید، تاریخچه تراکنش و مسیرهای تأیید خودکار SMS و ارز دیجیتال در صورت پیکربندی.
- **TwinConnect چندبرندی:** تنظیم لوگو، رنگ، اطلاعات تماس و آدرس پنل اپ برای مدیر و هر نماینده به‌صورت مستقل؛ دسترسی موتور اتصال به سیستم‌عامل و نسخهٔ اپ وابسته است.
- **۱۶ خانواده VPN و Proxy:** شامل SOCKS5 احراز هویت‌شده، وضعیت واقعی موتور روی هر نود و محدودسازی پروتکل‌ها براساس پلن.
- **زیرساخت پیشرفته:** مدیریت مستقل نودها، تونل‌های ایران و خارج، مسیرهای خروجی، عیب‌یابی، جابه‌جایی مسیر و گزینه‌های دسترسی اضطراری DNS.
- **فروش، نمایندگی و پشتیبانی:** پلن‌های دسته‌بندی‌شده، اعتبار حجمی، دوره آزمایشی، ارسال پیام همگانی ربات، اعلان تحویل و وضعیت آنلاین اشتراک.
- **مدیریت حرفه‌ای:** تاریخچه قابل جستجوی عملیات ادمین، بکاپ داده‌ها با ارسال اختیاری به تلگرام، بروزرسانی امن و بخش مدیریت لایسنس.

## قابلیت‌های عملیاتی مهم

TwinPanel فروش، تحویل اشتراک، حسابداری، مدیریت نودها و اتصال کاربران را در یک پنل متمرکز می‌کند:

- **تمدید بدون تغییر کانفیگ:** تمدید رزروی بعد از پایان زمان یا حجم اشتراک فعلی فعال می‌شود و اطلاعات اتصال کاربر حفظ می‌گردد.
- **حسابداری قابل پیگیری:** کیف پول مشتری و نماینده، بررسی رسید، تاریخچه پرداخت و تمدید و ثبت تغییرات دستی مدیر.
- **زیرساخت و پایداری:** نصب و تعمیر نودها، وضعیت پروتکل‌ها، مدیریت تانل و مسیر خروجی، مسیر DNS اضطراری، پایش و عیب‌یابی.
- **فروش و پشتیبانی:** ربات تلگرام، تحویل اطلاعات اتصال، اعلان‌ها، ارسال پیام همگانی، پشتیبانی و بکاپ و بازیابی اطلاعات.
- **نمایندگی و لایسنس:** مدیریت پلن‌ها و دسترسی پروتکل، اعتبار حجمی نمایندگان، برندینگ اختصاصی و مدیریت مرکزی لایسنس.

## TwinConnect — اپ هوشمند اتصال

**TwinConnect اپ هوشمند همراه TwinPanel است** که سرورها و کانفیگ‌های مجاز هر اشتراک را از سیستم مرکزی دریافت می‌کند تا کاربر نیازی به مدیریت دستی تک‌تک کانفیگ‌ها نداشته باشد.

- **پلتفرم‌ها:** ویندوز، اندروید، macOS و iOS؛ وضعیت انتشار و موتورهای قابل استفاده در هر نسخه و سیستم‌عامل متفاوت است.
- **اتصال هوشمند:** Quick Connect، انتخاب سرور و پروتکل، حفظ انتخاب کاربر، دسته‌بندی کشورها و نمایش وضعیت اتصال.
- **اطلاعات لحظه‌ای:** پینگ، IP، مدت اتصال، سرعت دانلود و آپلود و وضعیت اشتراک در نسخه‌های پشتیبانی‌شده.
- **هماهنگی با پلن:** نمایش فقط سرورها و پروتکل‌های مجاز و دارای کانفیگ معتبر؛ حجم، انقضا، تعداد دستگاه مجاز و تمدید رزروی در بخش‌های مربوط.
- **امکانات شبکه و امنیت:** Kill Switch، Split Tunneling انتخابی برنامه‌ها، عیب‌یابی DNS و مسیر اتصال اضطراری با توجه به پشتیبانی واقعی هر پلتفرم.
- **برند اختصاصی:** لوگو، رنگ‌بندی، اطلاعات پشتیبانی و تمدید مخصوص نماینده از طریق TwinPanel.

**نکته مهم:** وجود یک پروتکل در پنل به معنی تکمیل موتور اتصال آن در همه نسخه‌های TwinConnect نیست. قابلیت‌های اتصال و امنیتی هر سیستم‌عامل باید پیش از اعلام نسخه پایدار آزمایش شوند.

## نصب سریع

روی Ubuntu 22.04 یا 24.04:

```bash
curl -fsSL https://raw.githubusercontent.com/matin111/twinpanel/main/install.sh | sudo bash
```

بعد از نصب، منوی مدیریت سرور با این دستور باز می‌شود:

```bash
twinpanel
```

یا:

```bash
tp
```

Installer نسخه Stable منتشرشده را از Manifest رسمی دریافت می‌کند و همان Source تأییدشده را نصب می‌کند؛ بدون Clone دستی، Deploy Key یا انتخاب Branch.

# ۱۶ خانواده پروتکل VPN و Proxy

TwinPanel **۱۶ خانواده پروتکل VPN و Proxy** را از یک Control Plane مدیریت می‌کند. فعال‌بودن هر پروتکل به Runtime نود، مجوز پلن و پشتیبانی کلاینت بستگی دارد.

## پروتکل‌های کلاسیک

| پروتکل | کاربرد |
|---|---|
| **Cisco / OpenConnect** | اتصال سازگار با AnyConnect |
| **OpenVPN** | VPN مبتنی بر TLS با پشتیبانی گسترده |
| **WireGuard** | VPN سبک و سریع لایه ۳ |
| **L2TP / IPsec** | سازگاری Native با سیستم‌عامل‌های مختلف |
| **V2Ray / Xray** | پروفایل‌های انعطاف‌پذیر VLESS/Xray و Transportهای مدرن |

## پروتکل‌های مدرن

| پروتکل | تمرکز اصلی |
|---|---|
| **Hysteria2** | QUIC/UDP، مناسب شبکه‌های Lossy و مسیرهای طولانی |
| **TUIC v5** | QUIC با Latency پایین |
| **AnyTLS** | TCP/TLS برای شبکه‌های محدود |
| **NaiveProxy** | HTTPS مرورگرمانند و Camouflage |
| **ShadowTLS v3** | TLS Camouflage |
| **Snell** | پراکسی رمزنگاری‌شده سبک |
| **Mieru** | پروتکل مدرن رمزنگاری‌شده |
| **TrustTunnel** | Tunnel مدرن مدیریت‌شده |
| **AmneziaWG** | نسخه Obfuscated مبتنی بر WireGuard |
| **Sudoku** | پروتکل مدرن مدیریت‌شده توسط TwinPanel |

## پراکسی مستقیم

| پروتکل | کاربرد |
|---|---|
| **SOCKS5** | پراکسی TCP با احراز هویت برای برنامه‌های سازگار؛ خود SOCKS5 رمزنگاری ذاتی ندارد |

TwinPanel وضعیت واقعی Adapter و Runtime هر پروتکل را نمایش می‌دهد و اگر Runtime آماده نباشد، آن را به‌صورت جعلی Online نشان نمی‌دهد.

# سیستم Tunnel

یکی از بخش‌های اصلی TwinPanel، لایه مستقل Tunnel بین ایران و Exit است.

```text
Client
  ↓
Iran Node
  ↓
Managed Tunnel / Transport
  ↓
Exit Node
  ↓
Internet
```

این معماری باعث می‌شود تغییر یا Repair تانل، الزاماً Credential کاربر را تغییر ندهد.

# دسترسی اضطراری DNS

TwinPanel علاوه بر VPN و تانل‌های معمول، بخش‌های مستقل **NetMod DNS / DNSTT** و **DNS Emergency Iran Relay** را برای شرایط محدودیت شدید اینترنت دارد.

- نصب و مدیریت DNSTT و سرویس SSH داخلی روی نودهای سازگار، همراه راهنمای رکوردهای DNS و لینک Import با قالب `nm-dns://` برای NetMod
- نصب / Repair، Health Check، مشاهده وضعیت و حذف سرویس
- عیب‌یابی DNS Resolver، MTU و آزمایش عملکرد مسیر
- گزینه ورودی DNS روی نود ایران و انتقال ترافیک به Exit از طریق تانل سالم موجود

این مسیرها اختیاری هستند و کارکردشان به دسترس‌بودن DNS، تنظیمات نود و پشتیبانی کلاینت وابسته است؛ هنگام قطع کامل شبکه، اتصال را تضمین نمی‌کنند.

# مدیریت لایسنس و آدرس اپ هوشمند

در **License Center** وضعیت لایسنس یا دوره آزمایشی، تاریخ انقضا، زمان باقی‌مانده و نسخه فعلی پنل نمایش داده می‌شود. مدیر می‌تواند لایسنس را فعال کند و آدرس HTTPS پنل را در فهرست مرکزی اپ TwinConnect ثبت یا ویرایش کند.

---

# بخش‌های اصلی پنل

| بخش | کاربرد |
|---|---|
| داشبورد | وضعیت کلی سیستم |
| کاربران | مدیریت حساب‌های مشتری |
| اشتراک‌ها | Lifecycle، حجم، تمدید رزروی، تاریخچه و Credential |
| پلن‌ها | محصولات قابل فروش |
| فروشگاه | خرید عمومی |
| پرداخت | سفارش، کیف پول، تراکنش، بررسی رسید و تأیید SMS/Crypto |
| نمایندگی | فروشندگان، پلن‌های مجاز، قیمت‌گذاری و اعتبار حجمی |
| نودها | سرورهای ایران و Exit |
| پروتکل‌ها | مدیریت ۱۶ خانواده VPN/Proxy و بررسی Runtime |
| تانل‌ها | مسیرهای Iran → Exit |
| Outbound | Routing و Egress |
| اپ هوشمند و برندینگ | لوگو، رنگ، راه‌های تماس، آدرس پنل و هویت مستقل نماینده در TwinConnect |
| DNS اضطراری | نصب و پایش NetMod DNS/DNSTT و Iran Relay |
| لایسنس | وضعیت، فعال‌سازی، انقضا و ثبت آدرس اپ |
| پشتیبانی | تیکت و ارتباط با مشتری |
| اعلان‌ها | Notification Center |
| سیستم و نگهداری | تنظیمات، امنیت، تاریخچه عملیات ادمین، Backup و Update Center |

# مسیرهای مهم

| مسیر | کاربرد |
|---|---|
| `/opt/twinpanel/current` | نسخه فعال |
| `/etc/twinpanel/backend.env` | تنظیمات Backend |
| `/etc/twinpanel/install.env` | تنظیمات نصب و Release |
| `/var/lib/twinpanel-backups` | Backupها |
| `/root/twinpanel-initial-admin.txt` | اطلاعات اولیه Admin |
| `/usr/local/bin/twinpanel` | دستور مدیریت SSH |

---

# نکات امنیتی

- فایل‌های `.env` و Secretها را عمومی نکنید.
- Private Key و API Token را داخل Git Commit نکنید.
- رمز Admin اولیه را تغییر دهید.
- بعد از اولین ورود فایل Credential اولیه را حذف کنید.
- برای آپدیت از Update Center یا CLI رسمی استفاده کنید.
- فایل‌های Release فعال را مستقیم روی سرور ویرایش نکنید.
- قبل از تغییرات زیرساختی Backup بگیرید.
